# Trust inventory of the Verus proofs

Generated by `scripts/trust-scan.sh` (scanned: `crates/`, `verus-bumpalo (pinned src)/`, `hashconsius (pinned src)/`; `target/` skipped). Do not edit by hand; rerun the script.

The declaration inventory below distinguishes assumed contracts, uninterpreted models,
and unverified execution candidates. These categories are not additive measures of trust:
one item can have multiple roles. Comments and string literals are ignored. All source
configurations are scanned (including test-util/tests); cfg reachability is not evaluated.
Counted kinds:

- `proof_axiom`: an external-body proof function; its ensures are axioms, not executable wrappers.
- `uninterpreted_spec`: an uninterpreted specification; meaning is supplied by contracts/hypotheses, not a body.
- `external_derive_claim`: an obeys_*_spec claim on a type with ignored external derives; audit the native derive.
- `unannotated_public_exec`: an executable public item (or trait-impl method) outside an enclosing verification annotation; a review candidate, not an axiom.
- `assume_specification`: a contract for an external (std/third-party) function that Verus assumes without proof.
- `external_fn_specification`: a contract for an external function, declared in the older attribute form; assumed.
- `external_body`: a function or type whose body Verus does not check; its signature contract is assumed.
- `external_type_specification`: makes an external type usable in verified code; `opaque` marks types whose fields are hidden.
- `external_trait_specification`: declares the specification of an external trait for verified code; its methods' contracts are assumed.
- `external`: an item Verus ignores entirely (`#[verifier::external]`); verified code cannot call it unless it has another spec.
- `admit`: `admit()`: closes a proof obligation without proof.
- `assume`: `assume(p)`: adds `p` as a fact without proof.
- `exec_allows_no_decreases_clause`: an executable function whose termination is not proved (its loops/recursion have no `decreases`).

An opaque external type is counted once with its type, not again as an external body.
Proof axioms are separated from executable external bodies. Unannotated-public-exec
is a conservative lexical candidate list: enclosing verus! and #[verus_verify] are
recognized, not arbitrary macro expansion. external_derive obeys claims are flagged
conservatively whenever their source file contains an external derive.
Not scanned: vstd (part of the pinned toolchain), Rust/std or other non-verified
dependencies. Their contracts are covered by the listed external boundaries.

## Interpretation and guarantee boundary

- Meaningful uninterpreted specifications include hash_coherent (native hash/eq faithfulness),
  snapshot_published (persistent codebook snapshots), diagnostic_output (callback meaning),
  arc_identity/reference_identity (restricted live-owner identity), and mutex/record validity,
  authority and observation tokens. These are not proved merely because they lack bodies;
  all uninterpreted declarations are enumerated below, including representation selectors.
- Successor search trusts GraphCaches::{successor_cache,successor_get,successor_put}: the
  native LRU must preserve cached successor values and keys, including misses/eviction.
- User Hash/Eq must obey the stated key laws and return normally. Panic, caught unwind,
  re-entry after a user Hash/Eq panic, and unsafe client duplication/corruption are outside
  the guarantee. Mutex leaves do not prove poisoning/recovery of a partially mutated map.
- Benchmarks no longer enable test-util in root/fuzz dev-dependencies. Production paths
  use the verified runtime,std,cache semantics and runtime analysis configuration; fault
  injection and work-counter configurations are not benchmark configurations.
  The two instrumentation regressions are preserved in tests/progress/counters.rs and
  run explicitly with `cargo test --locked -p junco-policy --features test-util --test progress counters::`.
  That opt-in native test feature is not part of the verified benchmark build.
  The diagnostic fuzz replay_curve example requires its separate work-probe feature;
  default fuzz all-target/benchmark builds do not activate those counters.
- The root RulePolicy evaluation glue is unverified: could_fire filtering, per-candidate
  TracePolicy compilation, decide-then-append, denied-event append in audit mode, and
  error-to-deny conversion are outside Validator::check's theorem.
- Root LockEvent/AgentEvent/FlowEvent retain public custom tagged enums, not tuple aliases.
  Their hand-written Event projections need R1 projection/arity laws and R4 component
  equality/hash laws. Analyzer use additionally needs surjectivity; the root crate is not
  a verified target. Changing the public component vocabulary is not a behavior-neutral derive.
- Existing TraceRule::clone's trusted leaf clones self.rule and the diagnostic Arc.
  A source-preservation contract on this leaf rests on that native clone, not a new proof axiom.

## Arc/reference identity audit (Verus 0.2026.10.04.426d8b0)

Arc<T> and &T are modeled by referent value, not native address. A pinned-toolchain
proof establishes equality of two Arc::new(0u64) results and two separate &0u64 locals
(2 verified, 0 errors). Native allocation addresses are therefore not recoverable from
arbitrary equal referent values.
Therefore the generic uninterpreted identity functions do NOT prove pointer injectivity.
The six audited leaves remain unchanged and rely on the following restricted invariants:

- share_store and borrow_store operate on non-Clone/non-Copy Store<E> with all fields
  pub(crate), no public field setters, and Store::new as its sole constructor. It obtains
  an owned linear RegistryBirth and a checked process-wide never-recycled u64 store id;
  id, history_registry, store_id_receipt and registry_birth are carried in the value.
  Existing lemma_registry_births_distinct, lemma_store_receipts_distinct and
  independently_constructed_stores_client prove independent constructions have distinct
  registry/id values. Persistent StoreIdReceipt alone is duplicable and is NOT freshness;
  the linear RegistryBirth plus authoritative issuance supply it. Safe moves preserve
  logical owner identity, but cannot leave two live independent owned Store values.
- CompiledRule::same_owner compares live Arc<Store<E>> allocations under that same
  construction invariant; a clone shares allocation. No generic Arc<T> pointer theorem
  or arbitrary-user-type injectivity is claimed.
- share_numeric_owner, borrow_numeric_owner and same_numeric_reference operate on
  non-Clone/non-Copy HistoryStore with pub(crate) fields, no public field setters, and
  HistoryStore::new as its sole constructor. Its static
  registry permanently retains one Arc per arity; equal arity shares that allocation,
  different arities have different domains lengths and hence different logical values.
  The singleton_valid constructor leaf supplies installation/mutex fidelity, not fresh
  identity; numeric_store_wf carries that fact without a separate proof axiom.
These construction facts justify the six restricted trusted leaves; they do not turn
the uninterpreted identity mappings themselves into proved address models. Adding a
constructor, Clone implementation or unsafe duplicator requires re-auditing this boundary.

## Approved key trust

Only decision 4's concrete internal-key axioms may add proof trust. Primitive-key and
Component2/3/4 compositional axioms are NOT approved. The canonical R4 hashing requirement
is a single uninterpreted hash_coherent hypothesis. A concrete u8/u32 event witness may
assume only its exact component-type hash premise and must prove all other bundle conjuncts.
Every actual proof axiom is enumerated below, including helper dependency axioms; counts
describe scanned source, not anticipated migration results. No arbitrary-user-key axiom is approved.
An assumed exec key-law introduction is also an axiom: native_constraint_key_laws is
reported under assume_specification when present, not proof_axiom. The latter counts external-body
proof functions only; it must not be mistaken for the total number of logical axioms.
