# Trust inventory of the Verus proofs

Generated by `scripts/trust-scan.sh` (scanned: `crates/`; `target/` skipped). Do not edit by hand; rerun the script.

Everything Verus checks is verified against its contract; the items below are the places
where a contract or fact is *assumed*. Matches in comments and string literals are ignored.
Counted kinds:

- `assume_specification`: a contract for an external (std/third-party) function that Verus assumes without proof.
- `external_fn_specification`: a contract for an external function, declared in the older attribute form; assumed.
- `external_body`: a function or type whose body Verus does not check; its signature contract is assumed.
- `external_type_specification`: makes an external type usable in verified code; `opaque` marks types whose fields are hidden.
- `external_trait_specification`: declares the specification of an external trait for verified code; its methods' contracts are assumed.
- `external`: an item Verus ignores entirely (`#[verifier::external]`); verified code cannot call it unless it has another spec.
- `admit`: `admit()`: closes a proof obligation without proof.
- `assume`: `assume(p)`: adds `p` as a fact without proof.
- `exec_allows_no_decreases_clause`: an executable function whose termination is not proved (its loops/recursion have no `decreases`).

An `external_body` attribute on an external type specification makes that type opaque and
is reported once, with the type. Not counted: `external_derive` (derived trait impls that
Verus ignores), `opaque`/`rlimit`/`spinoff_prover` (proof-engineering controls), and the
hypotheses of theorems (stated in each `requires`). Not scanned: `vstd`, Verus's standard
library, which is part of the pinned toolchain.
Also not scanned: the verified helper crates `verus-bumpalo` and `hashconsius`, which
`history-store` takes as pinned git dependencies; Verus verifies them as dependencies.
