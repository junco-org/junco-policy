### F1 — MAJOR: every event type in the evaluation carries the whole of `event_obligations` unproved, not just hashing
- **Paper:** appendix.tex:1068-1075 ("All typed guarantees … rest on stated hypotheses … All but the last are proved for the built-in tuple event types"); appendix.tex:~891-894 ("hypotheses proved for concrete event types except the hashing law … so that no guarantee holds vacuously"); eval.tex:22-27 ("all benchmarks are built in a configuration that Verus verifies"); main.tex:105-107 (conclusion).
- **Artifact:** no benchmark uses a built-in tuple event.
  - Synthetic traces (`fuzz/benches`, the source of lock.dat/deny.dat) and `benches/validator.rs:557`, `benches/progress.rs:186` use `LockEvent<P,R>` (src/model.rs:67-71): "Hypothesis (D4): this crate is not verified, so `event_laws::<LockEvent<P, R>>` (R1) is assumed, not proved".
  - AgentDojo uses `FlowEvent` (src/policy/flow/mod.rs:87-91, same comment).
  - RegExLib uses `Char` (benches/smt/regexlib_subset.rs:13 `impl Event for Char`). RE# uses `Symbol` (benches/resharp/translate.rs:17).
  - None of these types has an `EventSpecImpl` or `PartialEqSpecImpl`. So `E::obeys_projection_spec()`, `component_spec` and `coordinate_spec` (event.rs:274-289) are the blanket `external_body` spec functions generated by `external_trait_extension`, and `LockComponent`/`FlowComponent`/`Char` equality has an uninterpreted `obeys_eq_spec`/`eq_spec`. Every conjunct of `event_obligations` (R4 hypotheses.rs:33-41) is an unproved hypothesis for them, and so is the projection/tag law: arity, projections, surjectivity, `Eq` faithfulness, equivalence and hashing.
  - The proved instances are only `(u32,u64)`, `(u8,u8,u8)` and `(u32,u8,bool)` (junco-core/src/verify/hypotheses.rs:104-128).
- **Why it matters:** a reader of the appendix concludes that only the hashing law is assumed for the measured system. In fact, for every measured configuration, all event-type hypotheses are assumed. VERIFY.md:145-147 and TRUST.md:406-407 say this; the paper does not.
- **Fix (paper):** in appendix "Trusted base" and eval.tex:22-27, add: "The evaluation's event types (`LockEvent`, `FlowEvent`, and the benchmark `Char`/`Symbol` types) implement `Event` by hand in unverified code; for them all four event-type hypotheses are assumed, not proved." **Fix (code, optional):** make `Char` a built-in tuple `((), u8, ())`, and give the root event types an `EventSpecImpl`/`PartialEqSpecImpl` inside a verified crate.

## 2. Per-contract review (question 2)

All of these are plausibly true of the real implementation unless noted.
- **NativeMap/NativeSet/NativeGroups** (history-analysis/src/native.rs:12-125; history-store/src/typed/map.rs:17-70): every semantic ensures is guarded by `key_laws::<K>() ==>`, and `insert_fresh`'s freshness requirement is too. Lookup returns "some representative eq_spec-equal to the key"; under `key_laws` plus freshness that is unique. `reserve_one` ensures only representatives unchanged plus `Err == AllocationFailed`. True of hashbrown 0.17 for terminating `Hash`/`Eq`. A panicking user `Hash`/`Eq` under the lock is outside the model (TRUST.md:408-409; the paper is silent).
- **Successor cache** (cache.rs:67-110): `successor_cache()` ensures `Some` with empty view (real: `NonZeroUsize::new(256)` is always `Some`). `get` ensures exact lookup and entries unchanged (LRU `get` changes only recency). `put` ensures the key is present with its value and every other entry is either the key or unchanged; this allows eviction and forbids fabrication. Unconditional hashing fidelity: see F5.
- **HistoryCursor::position** (cache.rs:127-139): `old.history == self.history && old.bindings == self.bindings`. `Bindings::eq` is verified equal to view equality (kernel.rs:194-217), which matches `cursor_key_eq`. ✓
- **Domain::path_*** (store.rs:213-238): BTreeMap get/insert/remove against the opaque `path_map`. ✓
- **Mutex/RwLock wrappers** (`NativeCoordinates`, `NativeHistoryKeys`, `NativeDomain`, `NativeRecord`, `NativeRecordReadGuard`, `NativeStoreIds`, `NativeBooks`; store.rs:680-930, 1806-1830; typed.rs:116-147, 416-457): the standard pattern of an invariant on acquire plus the callback's frame obligation on release. - **Identity** (`borrow_numeric_owner`, `same_numeric_reference`, `share_numeric_owner`, `share_store`, `borrow_store`, `same_owner`, `HistoryStore::new`, `NativeRecord::clone`): faithful given the singleton/unique-id argument (history_assumptions.rs:49-58; confirmed only one `HistoryStore` literal and no `Clone` on `Store`). `arc_identity`/`reference_identity` are functions of the pointee value. The contracts would be false if a second `HistoryStore` of the same arity were ever built; nothing in the code does so.
- **Policy/trace adapters** (rule.rs:23-104, trace.rs:38-317, evaluate.rs:69-174): field moves plus callback storage and invocation. The uninterpreted `id`/`diagnostic_output` have a consistent model (distinct opaque values per allocation). `TraceRule::clone`: see F7.

- **ObservationWorld::try_reserve_*** (observation.rs:83-125): ensures contents unchanged on any result. ✓
- **assume_specifications** (history_assumptions.rs:63-208): checked against the std and smallvec 1.16.2 semantics.
  - `push`/`resize` have no capacity precondition; the real functions panic or abort on overflow or OOM, which is outside partial correctness.

  - No contract asserts more than the implementation does.

## 3. Axioms (question 3)
- `(ConstraintId, RegexId)`, `(RegexId, RegexId)`, `(TestId, TestId)`: `ConstraintId = u32` (constraint.rs:332). The ids are `u32` newtypes with derived `Hash`/`Eq`/`Ord` (kernel.rs:63-69), and `eq_spec` is `self@ == other@` (kernel.rs:959-962). Tuples compare and hash field by field. True.
- `Constraint`: derived `Hash` over `Vec<RegisterConstraint>`, while `PartialEq` is **verified** equal to `constraint_key` equality (constraint.rs:917-930). `RegisterConstraint::eq` is verified equal to `register_key` equality (constraint.rs:875-905): `Equals(v)` ↦ `(Some(v), [])`, `Differs(vs)` ↦ `(None, vs)`. That is exactly what the derived `Hash` hashes (discriminant + payload; SmallVec hashes as a slice). True.
